# Калькулятор длины ножей штанцформы

Локальное веб-приложение для расчёта суммарной длины линий реза (нож, красный)
и линий биговки (зелёный) в PDF- или AI-макете, и итоговой стоимости
изготовления штанцформы.

Работает полностью офлайн, без сервера и без интернета — вся логика на чистом
HTML/CSS/JS, PDF разбирается локальной копией [pdf.js](https://mozilla.github.io/pdf.js/).

## Запуск

Самый простой способ — просто открыть `index.html` двойным кликом в браузере
(Chrome или Edge).

### Если файл не открывается через file://

Некоторые версии Chrome блокируют загрузку web worker'а из локального файла
(`file://...pdf.worker.min.js`) из-за ограничений безопасности. Приложение
само пытается подстраховаться (pdf.js в этом случае переключается на
однопоточный режим в основном потоке), но если после загрузки PDF-файла
появляется ошибка открытия — запустите папку проекта через простейший
локальный сервер и откройте адрес из браузера:

```bash
# находясь в папке проекта
python -m http.server 8000
```

Затем откройте `http://localhost:8000/` в браузере.

(Подойдёт любой другой простейший статический сервер — `npx serve`,
встроенный сервер VS Code Live Server и т.д. Требование то же самое:
он должен просто отдавать статические файлы, никакой сборки не нужно.)

## Как пользоваться

1. Перетащите PDF или AI-файл в область загрузки, либо нажмите «Выбрать файл».
   AI-файл должен быть сохранён с опцией **«PDF-совместимый»** — тогда его
   можно открыть как обычный PDF.
2. Приложение разбирает файл постранично. **Каждая страница файла получает
   свой независимый, полностью самостоятельный блок-отчёт** — как если бы это
   был отдельный однострадничный файл: свой заголовок, своя цена за метр,
   своя сводка длин, своя итоговая стоимость, своё превью и свои кнопки
   экспорта. Страницы никак не суммируются между собой — все показатели
   разделены.
   - Заголовок блока — имя файла. Если в файле несколько страниц, в скобках
     добавляется «(Монтажная область N)»; если страница одна — ничего не
     добавляется, заголовок — просто имя файла.
3. В каждом блоке введите цену за 1 погонный метр (грн.) для этой страницы —
   стоимость штанцформы пересчитывается мгновенно, без повторной загрузки
   файла. Она округляется до целого числа и помечается маленькой звёздочкой
   у заголовка — это приблизительная сумма, точная стоимость определяется
   после просчёта у подрядчика (сноска под блоком стоимости).
4. Кнопка «Скопировать результат» в блоке страницы копирует в буфер обмена
   краткую текстовую сводку по этой странице: имя файла (с пометкой
   монтажной области, если страниц несколько), формат печатного листа, цену
   за 1 м.п., итоговую длину и стоимость штанцформы (без сноски и без
   звёздочки — только числа).
5. Кнопка «Скачать отчёт (PNG)» в блоке страницы сохраняет картинку,
   повторяющую вид этого блока: заголовок, сводные плашки (биговка/нож/общая
   длина, с цветными кружками), блок стоимости, сноску по центру, превью
   контура и площадь листа/заполнение/отход — готовый отчёт по одной
   странице можно переслать или распечатать отдельно от остальных. Картинка
   рендерится минимум в 2x-разрешении (даже на обычных, не Retina-экранах),
   чтобы текст и линии оставались чёткими при масштабировании и печати.
6. Кнопка «Скопировать отчёт (PNG)» копирует ту же картинку сразу в буфер
   обмена (можно вставить прямо в чат/письмо), без сохранения файла на диск.
   Требует поддержки Clipboard API для изображений в браузере; если браузер
   отказывает — появится подсказка воспользоваться кнопкой «Скачать».

## Как определяются цвета

Используется мягкое (нестрогое) распознавание по оттенку (hue), а не точное
совпадение с эталонным CMYK:

- Нож (красный): оттенок в пределах ±35° от чистого красного (0°).
- Биговка (зелёный): оттенок в диапазоне 75–165° (вокруг чистого зелёного, 120°).
- Линия учитывается, только если достаточно насыщена (не серая/чёрная/белая) —
  порог насыщенности 15%.
- Учитывается цвет обводки (stroke), а не заливки.
- Такое распознавание ловит любые «красноватые»/«зеленоватые» линии независимо
  от того, заданы они через CMYK, RGB или spot-цвет, и не требует точного
  совпадения с M100/Y100 или C100/Y100.
- Линии, чей цвет не попадает в эти диапазоны (чёрный, синий, жёлтый и т.д.),
  игнорируются и не входят в расчёт — они видны на превью страницы бледно-серым
  для наглядности, а их количество пишется в консоль браузера (F12 → Console).

## Визуальное превью

Внутри каждого блока страницы, под сводкой и стоимостью, — «Формат печатного
листа: …» с размером в мм (крупным, жирным текстом — эта подпись важнее
прочего; для распознанных стандартов указывается название — A4, A3 и т.д.,
для нестандартного размера название опускается, остаются только мм), ниже —
миниатюра (длины биговки/ножа отдельно у картинки не дублируются — они уже
показаны в сводных плашках самого блока, с цветными кружками зелёный/красный
перед подписями «Биговка»/«Нож»). Вокруг
пунктирной рамки (монтажная область — размер страницы в файле) со всех четырёх
сторон одинаковый белый отступ; снизу и справа от рамки подписаны
соответствующие размеры в мм (ширина — снизу, высота — справа, сверху и слева
не дублируются). Поверх рамки отрисованы найденные линии — зелёным биговка,
красным нож, бледно-серым — линии, которые не попали ни в один из диапазонов
цвета (полезно для проверки, почему что-то не посчиталось). Отображение в
браузере и в PNG-отчёте выглядит одинаково.

Под миниатюрой — три расчётных показателя (площадь — в квадратных метрах,
округление до тысячных):

- **Площадь листа** — площадь всей монтажной области (ширина × высота листа).
- **Заполнение** — площадь и процент, которые занимает сама деталь: площадь
  внутри крайних (внешних) замкнутых контуров ножа. Вложенные контуры
  (внутренние вырезы/отверстия в детали) не прибавляются повторно, а
  отдельные контуры на одном листе (несколько деталей рядом) суммируются.
  Линии биговки в этот расчёт не входят — они не задают физическую границу
  реза.
- **Отход** — обратная величина в процентах (100% − заполнение): доля листа,
  которая не входит в контур детали.

Контур ножа не обязан быть нарисован одним замкнутым путём в самом файле:
если он разбит на несколько отдельных незамкнутых отрезков (например, каждая
сторона фигуры — отдельный `stroke()`, либо между сегментами оставлены
намеренные технологические «мостики»/просечки — стандартная практика
штанцевания, чтобы деталь не выпадала из листа при резке, обычно до
нескольких мм), приложение перед расчётом площади автоматически «сшивает»
такие фрагменты по ближайшим (с допуском ~7 мм) концам в замкнутый контур.
Это влияет только на расчёт заполнения/отхода — на длину ножа/биговки не
влияет никогда, она считается независимо от того, замкнут контур или нет.

Ограничение сшивания: если в одной точке сходится больше двух отрезков
(Т-образное пересечение), может быть выбран не тот путь дальше. А фрагмент,
у которого действительно нет пары нигде в файле (настоящий разрыв в контуре),
так и останется незамкнутым и не попадёт в расчёт площади — это уже отражает
проблему в самом файле, а не в алгоритме.

## Ограничения

- Цвета, заданные через именованные (spot/Separation) цветовые пространства,
  распознаются только эвристически (по числу компонент); гарантированно
  корректно обрабатывается прямой CMYK/RGB/Gray.
- Дедупликация наложенных линий — эвристика (совпадение длины, bounding box
  и средней точки контура с округлением ~0.2 мм), не строгий топологический
  анализ. Ловит явные полные наложения, но не гарантирует 100% результат на
  сложных частично перекрывающихся контурах.
