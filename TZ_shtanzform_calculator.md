# ТЗ: Калькулятор длины ножей штанцформы (веб-приложение)

## 1. Назначение

Локальное веб-приложение (один HTML-файл или папка HTML+CSS+JS, без сервера, открывается двойным кликом в браузере через `file://`) для автоматического расчёта суммарной длины векторных линий в PDF- или AI-файле (AI сохранён как PDF-совместимый, открывается как обычный PDF) с целью расчёта стоимости изготовления штанцформы (высечки).

Линии на макете штанцформы бывают двух типов:
- **Красные** — линии реза ("нож")
- **Зелёные** — линии биговки ("биговка")

Приложение должно посчитать длину каждого типа отдельно, общую длину, и итоговую стоимость на основе введённой пользователем цены за 1 погонный метр (м.п.).

## 2. Технологический стек

- Чистые **HTML + CSS + JavaScript**, без сборщиков и npm — всё должно работать напрямую через открытие `index.html` в браузере (Chrome/Edge).
- Парсинг PDF — библиотека **pdf.js** (Mozilla).
  - **Важно**: файлы `pdf.js` (`pdf.min.js`, `pdf.worker.min.js`) должны быть скачаны и лежать локально рядом с `index.html` (в подпапке `/lib`), а не загружаться с CDN — чтобы приложение работало полностью офлайн.
  - Учесть, что при запуске через `file://` браузер может блокировать web worker из локального файла из-за CORS/`file://`-ограничений. Нужно предусмотреть fallback: если worker не грузится — работать в main thread (`disableWorker` / `GlobalWorkerOptions.workerSrc` настроить на локальный путь; если не сработает — задокументировать в README, что нужно открывать через простейший локальный сервер, например `python -m http.server`, как запасной вариант).
- Никаких сторонних UI-фреймворков — простой, лёгкий, самописный JS.

## 3. Работа с входным файлом

- Загрузка файла двумя способами:
  1. Drag-and-drop в выделенную зону.
  2. Кнопка "Выбрать файл" (`<input type="file">`).
- Принимаемые форматы: `.pdf` и `.ai` (файл `.ai` обрабатывается как PDF — pdf.js должен уметь его открыть, так как это PDF-совместимый формат; если parsing не удался — показать понятную ошибку "Не удалось открыть файл. Убедитесь, что AI-файл сохранён с опцией 'PDF-совместимый'").
- После загрузки — показать имя файла, количество страниц, кнопку "Рассчитать" (или расчёт запускается автоматически сразу после загрузки — на усмотрение реализации, но лучше дать пользователю увидеть, что файл принят, до начала расчёта).

## 4. Многостраничные файлы

- Если в PDF несколько страниц/артбордов — **обрабатывать каждую страницу отдельно** и выводить результат по каждой странице по порядку (Страница 1, Страница 2, ...), плюс **итоговую сводную сумму** по всем страницам внизу.

## 5. Определение масштаба

- Документ уже в реальном размере (1:1). Единицы PDF (points, 1/72 дюйма) переводятся напрямую в метры:
  ```
  метры = длина_в_points * 0.0254 / 72
  ```
- Никакого ручного ввода масштаба не требуется.

## 6. Детекция цвета линий

- Цвета заданы в **CMYK**:
  - Красный (нож): `M=100%, Y=100%` (C=0, K=0)
  - Зелёный (биговка): `C=100%, Y=100%` (M=0, K=0)
- Допустимое отклонение (толерантность) — **±15%** по каждому CMYK-каналу от эталонных значений.
- Проверять цвет **обводки (stroke color)** векторного пути/линии (не заливку — линии реза не имеют заливки).
- Если у pdf.js путь описан в RGB (после конвертации библиотекой) — реализовать конвертацию CMYK→RGB для сравнения, либо, если pdf.js отдаёт исходные CMYK-компоненты операторов (`k`/`K` в content stream) — использовать их напрямую для точности. Приоритет — работать с сырыми операторами content stream, если это осуществимо, для максимальной точности перед тем, как полагаться на конвертированный RGB.
- Линии, чей цвет не попадает ни в один из двух диапазонов (с допуском) — **игнорировать** (не учитывать в расчёте, но можно посчитать и вывести в консоль/отдельным незаметным счётчиком "прочие линии — N шт." для отладки).

## 7. Расчёт длины линий

- Нужно пройти по всем векторным объектам (path/line/curve) на странице, определить их сегменты (`moveTo`, `lineTo`, `curveTo`/bezier, `closePath`) и посчитать длину:
  - Прямые сегменты — обычное евклидово расстояние между точками.
  - Кривые Безье — длина приближённо вычисляется через разбиение кривой на N маленьких отрезков (адаптивная триангуляция или фиксированное разбиение с достаточным количеством шагов, например 20–50 сегментов на кривую, для приемлемой точности).
- Учитывать также трансформации (matrix transform) страницы/группы, применяемые к координатам путей, чтобы длина считалась в правильной системе координат страницы.

## 8. Устранение дублей (наложенных линий)

- Если один и тот же рез задублирован (два одинаковых/почти одинаковых по геометрии path наложены друг на друга) — пытаться определять и убирать явные дубли перед суммированием.
- Практический подход: 
  - Округлять координаты точек пути (например, до 0.1–0.5 мм) и сравнивать пути на полное или очень близкое совпадение геометрии (та же последовательность точек ± небольшая погрешность, либо совпадение bounding box + длины + средней точки).
  - Если path полностью совпадает с уже обработанным path того же цвета — не учитывать его длину повторно.
- Это не обязано быть идеальным алгоритмом поиска дублей (не топологический анализ) — достаточно эвристики, которая ловит **явные** полные наложения одного пути на другой.

## 9. Ввод стоимости и расчёт цены

- Поле ввода: **"Стоимость ножа за 1 м.п."** — числовое поле, единицы измерения — **грн.** (одна цена применяется и к резу, и к биговке, по условиям задачи это единая ставка).
- После расчёта длины показать:
  - Длина биговок (зелёные), м.п.
  - Длина ножей (красные), м.п.
  - **Общая длина** (биговка + нож), м.п.
  - **Общая стоимость** = общая длина (м.п.) × стоимость за 1 м.п. (грн.)
- Все длины округлять до 2 знаков после запятой (м.п.), стоимость — до 2 знаков (грн.).
- Расчёт стоимости должен обновляться "живо" при изменении поля цены (без повторной загрузки/парсинга файла).

## 10. Результат и экспорт

- Результаты выводятся на экране в структурированном, красиво оформленном виде (см. дизайн ниже), с разбивкой по страницам и итоговой сводкой.
- Кнопка **"Скопировать результат"** — копирует в буфер обмена текстовую сводку результата (например: имя файла, по каждой странице — длина биговки/ножа, итог по всем страницам, цена за м.п., итоговая стоимость). Формат простого читаемого текста, например:

  ```
  Файл: shtanz_01.pdf
  Страница 1: биговка 2.35 м.п., нож 4.10 м.п.
  Страница 2: биговка 1.20 м.п., нож 3.05 м.п.
  ---
  Итого биговка: 3.55 м.п.
  Итого нож: 7.15 м.п.
  Итого общая длина: 10.70 м.п.
  Цена за 1 м.п.: 25 грн.
  Итоговая стоимость: 267.50 грн.
  ```

## 11. Дизайн (UI/UX)

Минималистичный, стильный, в духе топовых брендов электроники (референс — Apple):
- Много "воздуха" (whitespace), крупные отступы.
- Нейтральная палитра: белый/светло-серый фон, тёмно-серый/чёрный текст, один сдержанный акцентный цвет для кнопок и активных состояний.
- Тонкая, современная типографика (системный шрифт: `-apple-system, "Segoe UI", Inter, sans-serif` или похожий).
- Скруглённые углы, мягкие тени, плавные transition/hover-эффекты на кнопках и drag-зоне.
- Drag-and-drop зона — визуально выделена пунктирной/тонкой рамкой, с понятной иконкой и текстом, реагирует на наведение файла подсветкой.
- Числовые результаты — крупным, лёгким по начертанию шрифтом, с чёткой иерархией (итоговая стоимость — самый заметный элемент на экране).
- Адаптивность не критична (использование локально на десктопе), но должно нормально выглядеть в окне браузера стандартных размеров (1280–1920 px).

## 12. Обработка ошибок

- Файл не PDF/AI или повреждён — понятное сообщение об ошибке.
- В файле не найдено линий нужных цветов — сообщение "Векторные линии биговки/ножа не найдены" (не путать с ошибкой загрузки).
- Слишком большой/сложный файл — не блокировать интерфейс насмерть; желательно показать индикатор загрузки/прогресса на время парсинга.
